## 1. 이번 작업 목표와 단계 게이트

사용자 추가 요청을 반영해 이미 구현된 P1을 보완한다. 이번 실행에서 구현할 범위는 아래 P1 추가 항목뿐이다.

1. 시청각실 음향조정실 한쪽에 앰프 랙, 마이크 장비와 식별 가능한 믹서 추가
2. 컴퓨터실 후방 수납장에 헤드셋과 예비 키보드·마우스 및 소형 수업/정비 도구 추가
3. 컴퓨터실 후방 자격증 취득 및 시험일 안내 게시판 추가
4. 기존 P1(피아노, 펼쳐진 의자, 비틀린 키보드/의자, 책장/헤드셋함)을 유지하고 회귀 검증

이번 보완과 기존 P1 전체 검증을 마친 뒤 `Codex 검증 대기`로 기록하고 즉시 멈춘다. P1 Codex PASS 전에는 P2/P3 코드를 구현하지 않는다. 이후 P2와 P3 요구사항은 아래에 고정해 두되, 각 단계는 별도 승인 후 진행한다.

## 4. P1 보완 구현 요구사항

### 4.1 시청각실 앰프·마이크·믹서

- 기존 음향조정실 데스크와 리필존(`x≈44, z≈33`)은 그대로 보존한다.
- 데스크 오른쪽 한쪽에 별도 장비 랙을 둔다. 권장 AABB는 `min [50.5, 7.5, 31]`, `max [54.5, 13, 35]` (중심 `[52.5, 10.25, 33]`)이며 무대/후방 계단 바닥에 안정적으로 접지하고 방 경계 안에 둔다. 실제 메쉬 치수에 맞게 조정하되 데스크 AABB와 겹치지 않는다.
- 랙 전면에는 파워 앰프, 무선 마이크 수신기, 케이블/패치 패널을 각각 알아볼 수 있도록 배치한다.
- 데스크 위에 기존 모니터 2대와 구별되는 믹서 콘솔을 만든다. 페이더 여러 개, 노브, 채널 라벨을 시각적으로 식별 가능하게 한다.
- 핸드 마이크 2개, 마이크 스탠드 1개, 정돈된 케이블을 추가한다. 장비가 리필 상호작용 지점을 가리거나 통로를 막지 않게 한다.
- 랙 전체 외곽에 맞는 AABB를 등록한다. 메쉬와 AABB가 일치하고 26개 스폰 및 기존 리필존 동작과 충돌하지 않아야 한다. 작은 장식은 불필요한 충돌체를 만들지 않는다.
- 전용 리소스/동적 상태가 있으면 `cleanupAvRoom()`에서 정리한다. 새 동적 효과는 이번 범위에 만들지 않는다.

### 4.2 컴퓨터실 후방 수납장과 추가 도구

- 기존 후방 전산 책장과 헤드셋 10개를 보존한다. 열린 카트에 품목을 억지로 겹쳐 놓지 말고 실제 구획이 보이는 다단 수납장으로 조정한다.
- 구분 가능한 수량으로 예비 키보드 2개와 예비 마우스 4개를 수납한다.
- LAN 케이블 코일, USB 허브, 케이블 타이 등 소형 수업/정비 도구를 2~4종 추가한다.
- 외곽 AABB는 확장된 가구 전체를 감싸고, 방 경계·후방 스폰·중앙 통로 이동성을 침해하지 않아야 한다. 기존 26개 스폰과 XZ 중첩은 0건이어야 한다.
- 모든 예비 주변기기는 맵에서 샘플 가능한 재질로 표현하고, 수납함/랙 본체만 필요한 수준의 충돌체를 둔다.

### 4.3 컴퓨터실 자격증/시험일 게시판

- 후방 벽면 또는 전산 책장 인접 벽면에 작은 게시판/안내문을 자연스럽게 붙인다.
- 배경 텍스트는 다음 내용을 포함한다.
  - `컴퓨터 자격 인증 취득 축하 — 학생 8명`
  - `다음 모의 자격증 시험일: 2026년 10월 24일(토)`
- 이는 게임 배경용 가상 안내문이다. 학생 실명이나 그 밖의 개인 식별 정보는 넣지 않는다.
- 게시판은 벽 표면과 평행하게 놓고 스폰/이동 동선을 침범하지 않는다. 문구는 실제 프리뷰에서 읽혀야 하며, CanvasTexture를 사용하면 전용 텍스처를 `cleanupComputerLab()`에서 dispose한다. 장식용이면 신규 충돌체는 추가하지 않는다.

### 4.4 기존 P1 회귀 및 플레이 검증

- 피아노, 펼쳐진 의자 5석/접힌 의자 55석, 키보드 4개, 돌출·회전 의자 4개, 기존 책장 및 후방 장비를 유지한다.
- 펼쳐진 의자 상단 발판은 실제 게임 연습 모드에서 플레이어가 올라서고 내려올 수 있는지 직접 확인한다. Node 구조 검사만으로 실제 착지를 PASS 처리하지 않는다.
- P0 의자 하부 블로커 12개와 `scripts/check_av_room_runtime_penetration.mjs` 576회 테스트의 100% 차단 결과를 재확인한다.

## 5. 다음 단계로 고정할 요구사항 (이번 작업에서 구현 금지)

### P2 — 마우스 20개

- 전체 24석 중 20석에 마우스를 두고 네 중앙 인접 좌석은 비워 둔다: `Row0 Col2`, `Row1 Col3`, `Row2 Col2`, `Row3 Col3` (0-based, 4행×6석).
- 마우스 외곽은 지우개 요정 크기(약 `1.2 × 0.7 × 0.5`)와 유사하게 한다. 권장 길이(Z) 1.1~1.2, 너비(X) 0.7, 높이 0.38~0.5.
- `collide: false`, `sample: true`. 네 빈 자리에는 마우스 메쉬가 없어야 한다.

### P3 — 화면 전원 상태와 무대 조명

- 모니터 총 24대 중 켜짐 18대, 절전 3대, 꺼짐 3대로 명확히 구분한다.
- 켜진 18대에는 코딩, 한글 문서, 그림판, 브라우저, 스크래치, 바탕화면의 6종 화면을 각 3대씩 배정한다. 켜진 화면은 한눈에 전원이 들어온 것으로 보이게 대비와 emissive를 확보한다. 절전은 어둡게, 꺼짐은 emissive 없이 검게 표현한다.
- 6종 CanvasTexture를 캐싱/공유하고 `cleanupComputerLab()`에서 전부 dispose한다.
- 시청각실 천장 프로젝터 라인(`Z≈5`) 좌우에 무대 조명 6기(좌우 각 3기)를 설치하고 렌즈에 4방향 반도어를 단다. 무대 방향 빔과 좌측 1번 조명의 느린 불규칙 깜빡임을 추가한다. 재빌드 후 조명/재질/지오메트리 누수 0건을 검증한다.

P2/P3 각 구현은 P1 PASS 후 별도 작업 지시를 받을 때만 시작한다.

## 6. 검사 및 브라우저 검증

실제 빌드 결과의 메쉬/AABB/샘플 속성을 단언하고 다음 검사를 실행한다.

```powershell
node --check maps/av_room.js
node --check maps/computer_lab.js
node scripts/check_av_room.mjs
node scripts/check_av_room_runtime_penetration.mjs
node scripts/check_computer_lab.mjs
node scripts/check_followup_maps.mjs
python scripts/98_check_preview_script.py
git diff --check
```

브라우저의 `maps/preview.html`에서 두 맵을 확인하고, 실제 `index.html` 연습 모드에서 시청각실 음향 랙·믹서·마이크, 컴퓨터실 수납물·게시판, 펼쳐진 좌석 실제 착지/이탈을 육안 검증한다. 양 맵 3회 재빌드/교차 전환 후 HUD 수량 불변, 콘솔/WebGL 오류 및 누수 0건을 확인한다. GUI 검증을 실행하지 못한 항목은 PASS로 추정하지 말고 미실행으로 보고한다. 증거는 저장소 밖 AGY 아티팩트 디렉터리에 둔다.

통합 스크립트가 환경 문제로 실패하면 성공으로 간주하지 않는다. 가능한 하위 검사를 개별 실행하고 원인을 분리해 보고한다.
