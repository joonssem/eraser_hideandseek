## 0. AGY가 작업 전에 반드시 읽을 지시

AGY는 코드를 수정하기 전에 이 문서 전체와 아래 파일을 UTF-8로 읽는다.

- [ ] `maps/README.md`
- [ ] `docs/05_new_maps_specification.md`
- [ ] `maps/art_room.js`
- [ ] `index.html`의 `ROOM_W`, `ROOM_D`, `WALL_H`, `MAPS`, `buildActiveMap`, `buildRoomShell` 정의
- [ ] `git status --short`로 기존 변경 파일 확인

다음 규칙은 모든 단계에 적용한다.

- [ ] 배포 파일 `index.html`은 **Codex가 통합을 승인하기 전까지 수정하지 않는다.**
- [ ] 한 번에 아래의 **한 단계만** 작업한다.
- [ ] 단계 완료 후 체크 표시, 변경 파일, 검사 명령, 실제 출력, 남은 문제를 보고하고 멈춘다.
- [ ] 실행하지 않은 검사를 `통과`라고 기록하지 않는다.
- [ ] 문서의 주장과 실제 코드가 다르면 코드를 억지로 맞추지 말고 차이를 먼저 보고한다.
- [ ] 기존 사용자 변경을 삭제하거나 되돌리지 않는다.
- [ ] 외부 이미지·GLB·음원 없이 Three.js 기본 지오메트리와 Canvas 텍스처만 사용한다.
- [ ] 커밋과 푸시는 사용자가 명시적으로 요청할 때만 한다.

## 1. 작업 진행 방식

각 단계는 아래 순서로 진행한다.

1. AGY가 해당 단계의 체크리스트만 수행한다.
2. AGY가 `AGY 완료 보고 양식`으로 결과를 남긴다.
3. 사용자가 Codex에 검증을 요청한다.
4. Codex가 파일 diff, 정적 검사, 수량 검사, 필요 시 브라우저 실행으로 독립 검증한다.
5. Codex 판정이 `PASS`일 때만 다음 단계로 진행한다.
6. `FAIL`이면 AGY는 지적된 항목만 수정한 뒤 같은 단계를 다시 제출한다.
